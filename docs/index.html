Sentiment Search — ROG-Dialog v2 Where does the sentiment signal live in short Slovenian dialogue? Six reports: datasets, two API probes, two local probes, a duration study.

Ivan Porupski — Jožef Stefan Institute. Reports are static HTML, hosted on GitHub Pages. Numbers come from the matrix run at misc/run_results/finetune_20261113_162724/ plus the OpenRouter batches in runs/; pipeline code is in scripts/.

1.ROG-Dialog v2 — data overview current
The three Slovenian corpora in play (ROG-Dialog v2, ParlaSpeech-SI, ParlaSent-SL). Modality, splits, label priors, duration and speech-rate stats. Read this first.
2.OpenRouter — text probing on the chopping board
Gemini Flash and Claude Haiku on ROG transcripts, zero-shot and few-shot, 3-class and 6-class. Baselines included. Will be re-run with full ROG once that matrix is in.
3.OpenRouter — audio probing shelved
Gemini Flash and Gemini Carbon on raw ROG audio. Zero-shot hits text-ceiling; few-shot destroys the audio prompt. Kept for reference; not the deliverable path.
4.Local — text fine-tuning current
3 XLM-R backbones × 7 training mixtures regression matrix. Parliament → dialogue transfer broken; SPR mixture holds up. Baselines + per-cell numbers.
5.Local — audio fine-tuning placeholder
The final-stretch deliverable: a transformer speech-sentiment regressor for SL dialogue. Nothing on the board yet.
6.Sentiment signal across duration on the chopping board
ROG F1 climbs with clip length then plateaus at ~0.65; ParlaSpeech stays flat near 0.9 across all lengths. Domain gap, not length. Being redone on full-ROG.

Each row is a single dial we changed with everything else held fixed, scored by the resulting change in macro-F1 on the 3-class task (ΔF1_3) and the % change on top of the "from" condition. Green = the knob helped; red = it hurt; yellow = flat / within noise. Rows use matched comparison: same model where applicable, same eval subset, same prompt otherwise unchanged. A † marks an eval-set swap (fine-tune cells evaluate on ROG-test, not on the 170-instance subset).

Why "% of from" and not "% of random floor"? Each row is a paired knob flip — the question is "did changing this one dial move the signal from where it already was?", not "how far is this cell from random guessing?" Using the "from" condition as the local baseline keeps each row's story self-contained. † fine-tune / backbone / mixture rows evaluate on ROG-test (n=434, 2 s-filtered) because the fine-tune matrix was not re-run on the 170-subset; everything else is on the 170-subset. Both subsets share the same gold-labelling pipeline, so direction of the delta transfers; absolute F1 cannot be compared across eval sets. Audio rows: Flash + Carbon on the 170-subset, shelved after few-shot destroyed the audio prompt. "Luna 0-shot" = openai/gpt-5.6-luna; "Carbon" = Gemini Carbon 4 (audio-native frontier tier). ★ = the pragmatic peak of the current OR context sweep (W ∈ {0, 10, 20, 30, 50}); see Report 2.
